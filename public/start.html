Part 1

Getting set up with Claude Code

You’re going to work on the new GFP website with Claude Code. It’s Claude, but it can open, change and save the website’s files on your Mac for you.

You tell it what you want in normal words, like “make the episode titles bigger”, and it does the fiddly bits.

What you need

  • Your Mac
  • Your Claude subscription (the one you already pay for)
  • About 30 minutes, once. After that it’s quick.

1 Install Claude Code

This is the only bit where you open Terminal on its own. Terminal is an app that’s already on your Mac: instead of clicking things, you type instructions. It looks a bit hacker-ish, but you’ll only ever type a few words in it.

  1. Press ⌘ Cmd + Space, type Terminal, and press Return. A window with a blinking cursor opens.
  2. Copy this, paste it into Terminal, and press Return:
    curl -fsSL https://claude.ai/install.sh | bash
  3. Lots of text scrolls past. Wait until it stops and the blinking cursor is back (usually under a minute).
  4. Quit Terminal completely (⌘ Cmd + Q). That’s the installing done.

How to paste things in: click a yellow Copy button on this page, click in the Terminal window, press ⌘ Cmd + V, then press Return.

2 Make a folder for the website in Finder

  1. Open Finder (the blue smiley face in your Dock).
  2. Click Documents in the left-hand sidebar.
  3. Right-click an empty bit of the window (or tap with two fingers on a trackpad) and choose New Folder.
  4. Name it GFP-Website and press Return.

Leave it empty. Claude will put the website in it.

3 Open Terminal “inside” that folder

Claude Code works on whichever folder Terminal is opened in, so open Terminal straight from the folder:

  1. Right-click the GFP-Website folder in Finder.
  2. Choose New Terminal at Folder. It’s near the bottom of the menu, sometimes inside Services or Quick Actions.
  3. A Terminal window opens, ready and pointing at your folder.

Can’t see “New Terminal at Folder”? Switch it on once: open System Settings → Keyboard → Keyboard Shortcuts… → Services → Files and Folders, tick New Terminal at Folder, then click Done.

Quick alternative: drag the GFP-Website folder onto the Terminal icon in your Dock. That does the same thing.

4 Start Claude

In that Terminal window, type this and press Return:

claude

The first time only, it asks a few setup questions

  1. Pick a colour theme: any is fine. Use the arrow keys, then press Return.
  2. How do you want to log in? Choose Claude account with subscription.
  3. Your web browser opens. Log in to Claude if asked, then click Authorize. Go back to Terminal.
  4. If it asks Do you trust the files in this folder?, choose Yes.

You’ll then see a box where you can type to Claude. You’re in! 🙌

If it says “command not found”: paste this, press Return, close the Terminal window, and open a new one from the folder (step 3):

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc

5 Paste in this message, and Claude does the rest

Copy the whole message below, paste it into Claude, and press Return. Claude will walk you through everything else, one step at a time: making a GitHub account (where the website’s files are kept), installing a couple of tools, downloading the website, and showing it to you.

Hi Claude! I'm Freddie, co-host of The Generic Foiling Podcast. My mate Ben has built our new website and I want to work on it with you. HOW TO TALK TO ME (please stick to this the whole time, today and every time after) - I'm not technical and I don't want to learn how websites work. Keep the techy stuff behind the scenes. Do it quietly and just tell me what's happened in plain, friendly English. - Don't show me code, commands, file names or error messages. If something goes wrong, tell me in one sentence what it means for me, then sort it. - No jargon. Say "save point" not commit, "put it live" not push or deploy, "get Ben's latest changes" not pull, and "your preview" for the version only I can see on my Mac. - One step at a time. When I need to click or type something, tell me exactly what, then wait for me to say I've done it. - Just before my Mac asks me to allow something, tell me in one line what it's for and whether it's safe to press Yes. The folder you're in right now (Documents > GFP-Website) is where the website should live. Please get me set up: 1. GITHUB ACCOUNT. The website is kept on GitHub, in Ben's project "benfgillespie/freddie". I don't have an account yet. Walk me through signing up at https://github.com/signup (free plan), confirming my email, and turning on two-factor login (a passkey with Touch ID is easiest, and remind me to save my recovery codes somewhere safe). Then tell me to message Ben my GitHub username so he can invite me, and how to accept the invite when the email arrives. Wait until I say I've accepted. 2. BEHIND-THE-SCENES BITS. Install whatever my Mac needs to work on the site (Git, the GitHub tool and Node.js) in the simplest way. If a box pops up asking to install "command line developer tools", tell me to click Install. Then help me log in to GitHub (I'll do the browser part), and set things up with my name and email. 3. GET THE WEBSITE. Download it into this folder, then read the CLAUDE.md file that comes with it. It contains the rules for how we work together, including two "gates" you must always follow: I check every change in my preview before you save it, and nothing goes live until you've told me exactly what will change and I've said yes. Follow those rules from now on. 4. SHOW ME IT. Open my preview in my browser. 5. A PRACTICE RUN. Help me make one tiny, harmless change, so I can see how each gate works: the "does that look right?" check in my preview, then putting it live, then seeing it on the real site. Talk me through what's happening at each gate as we go. 6. CHEAT SHEET. Finish with a short, friendly list of things I can say to you: make a change, see it, put it live, get Ben's latest changes, and undo something. If you get stuck on anything, write me a short message I can copy and send to Ben.

Now and then your Mac will ask permission for Claude to do something. Claude tells you what it’s for just before, so you know when it’s fine to choose Yes (press Return).

If it asks for your Mac password, type it and press Return. Nothing appears on screen while you type. That’s normal, it’s a security thing.

★ Every time after that

  1. In Finder, go to Documents.
  2. Right-click GFP-Website → New Terminal at Folder.
  3. Start Claude:
    claude
  4. Ask for what you want, in normal words.

Things you can say

  • “Open my preview again” (Claude opens it for you when you start)
  • “Change the homepage headline to …”
  • “Use the photo called liam-new.jpg in my Downloads folder for Liam’s picture”
  • “The shop looks squashed on my phone. Can you fix it?”
  • “Undo that last change”
  • “Put it live”: Claude lists exactly what will change on the real site and waits for your “yes”. A minute later, it’s online.
  • “Get Ben’s latest changes”: Claude does this by itself when you start, but you can ask any time.

Handy to know

  • Two safety gates: after every change, Claude shows you the result in your preview (only you can see it) and asks “Does that look right?”. Nothing goes on the real site until you’ve said yes to putting it live.
  • The online version is at genericfoilingpod.com. Open it on your phone or send it to Liam. It only changes when you say yes to putting something live.
  • Stuck? Tell Claude exactly what you see. You can drag a screenshot straight into the Terminal window.
  • Nothing can really break. Every saved version is kept, so you can always go back.
  • To leave Claude: type /exit and press Return, or just close the window.

Moving the GFP site off WordPress: costs & how it all fits together

What changes, what it costs, and how the shop and payments would work if you switch genericfoilingpod.com to the new site.

Prices checked 21 October 2026. Card fees are the providers’ standard UK rates. Rough conversions use $1 ≈ £0.78.

The short version

  • Hosting goes from “something you pay Hostinger” to £0. The site runs on Ben’s Vercel account, which he already pays for, and the GFP site fits comfortably inside it.
  • The domain, podcast hosting and newsletter don’t change.
  • For the shop, we recommend Stripe Payment Links: no monthly fee, about 2.3% on a typical tee order, and checkout with Apple Pay and Google Pay.
  • Avoid Snipcart (what the new site is wired for at the moment) unless you sell more than about £780 of merch every month. Below that it’s a flat ~£16/month on top of card fees.
  • ⚠️ The domain expires on 23 November 2026. Renew it whatever you decide.

Why there’s nothing to “run”

WordPress is a program running on a server: it needs updates, plugin renewals and security patches, and it slows down as plugins pile up. The new site is just ready-made pages. There’s nothing to update or hack, and it loads much faster.

The shop & taking payments

You sell four items (three tees and the beanie) at £12–25. At that size, the big question is whether a shop tool’s monthly fee is worth paying. Here are the realistic options:

Option A: Stripe Payment Links Recommended

  • Each product gets a Buy button that opens Stripe’s own secure checkout page, with dropdowns for size and colour.
  • Customers pay by card, Apple Pay or Google Pay. Stripe collects their delivery address and emails them a receipt.
  • You see each order in the Stripe app (with the size, colour and address) and post it as you do now. Money lands in your bank account, usually within a few days.
  • Cost: no monthly fee. 1.5% + 20p per sale on standard UK cards (2.5% + 20p on European cards, 3.15% + 20p on other international cards).
  • Downside: no basket. Someone wanting a tee and a beanie checks out twice, or you add a ready-made “Tee + Beanie bundle” link.

Option B: Snipcart + Stripe (what the new site is built with now)

  • A proper basket that slides out on the site, so customers can buy several things in one checkout.
  • Cost: Snipcart charges $20/month (~£16) whenever sales are under $1,000 (~£780) a month, and 2% of sales above that. That’s on top of Stripe’s 1.5% + 20p.
  • Billed in US dollars, so the cost moves with the exchange rate.

Option C: Shopify Starter

  • About £5/month. You set the products up in Shopify and drop “Buy” buttons onto the site. It handles stock and shipping labels, which is handy if merch grows.
  • Card fees on top. Check Shopify’s UK page for the current Starter rate before choosing this.

Other payment details

  • Whose account? The Stripe account should be in the podcast’s name (Freddie and/or Liam), paying into your bank account, not Ben’s. Setting it up takes about 15 minutes, with ID and bank details.
  • PayPal: Stripe’s checkout covers cards, Apple Pay and Google Pay, which is most people. If you want PayPal as well, it can be added, but it costs more (2.9% + 30p for UK PayPal payments).
  • Disputes (someone tells their bank “I didn’t get it”) cost £20 each with Stripe, so keep proof of postage.
  • Old orders: export your WooCommerce order and customer history before the WordPress site is switched off.

What the switch involves

  1. Renew the domain at WordPress.com before 23 November 2026.
  2. Set up Stripe in the podcast’s name and create a Payment Link for each product (Claude can walk you through it). Then we swap the site’s shop buttons over.
  3. Switch on the contact form so messages reach the GFP Gmail.
  4. Redirect old addresses so existing links keep working: /about-us → /about, /episodes-list → /episodes, and the old episode pages → the episodes list.
  5. Point the domain at Vercel. This means changing two settings in WordPress.com’s domain panel. Ben does the Vercel side. The site switches over within an hour or so, with no downtime.
  6. Check everything, then export your WooCommerce orders and cancel Hostinger (and any plugin subscriptions).

Good to know: the site’s files live on GitHub and its hosting is on Ben’s account. If you ever want it fully separate from Ben, it can move to your own GitHub account and your own hosting in an afternoon. Cloudflare Pages and Netlify both have free plans that allow a shop. The domain, Stripe, Mailchimp and the podcast feed are all yours already.
